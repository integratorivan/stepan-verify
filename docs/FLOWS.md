# Язык карты флоу

Карта флоу проекта — это навигация всего приложения и каталог фич словами пользователя: **откуда приложение стартует и куда из каждого экрана можно перейти**, **какие фичи есть и какими шагами их проходят**, **что доказывает, что они работают**. Карта лежит в репозитории проекта и её читают и люди (экран «Флоу» в Stepan), и агенты (скилл `stepan-verify-flows`, переменная `$STEPAN_VERIFY_FLOWS`).

```text
.stepan_verify/flows/
  app.yml              навигация: старт, экраны, переходы
  features/<id>.yml    одна фича на файл
  .sync.yml            служебное (с какого коммита сверена) — руками не трогать
```

Файлы похожи на YAML и открываются любым редактором, но читает их свой построчный парсер: двоеточия внутри текста и маршруты вроде `/catalog/[id]` его не ломают, а ошибки показываются с файлом и строкой.

```sh
stepan_verify flows check [<repo>]   # ошибки и висячие ссылки (экран не описан, фичи нет)
stepan_verify flows fmt [<repo>]     # переписать файлы в каноническом виде
```

## Общие правила

- Поле: `ключ: значение`. Список: `[a, b]` или строки `- a` под ключом.
- Отступы — пробелами (табуляция — ошибка).
- Комментарий: `#` в начале строки, или `  #` (два пробела) после текста. `задача #5` остаётся текстом.
- Значение можно взять в кавычки `"…"`, если нужно сохранить пробелы по краям.

## app.yml — навигация всего приложения

```yaml
app: Stepan
start: Запуск
areas: [Сессии, Задачи, Документы]   # порядок областей в каталоге

screens:
  Запуск:
    -> Дашборд: открыть приложение
  Дашборд:
    route: /
    about: живые сессии и недавние проекты
    -> Сессия: клик по карточке (Продолжить сессию)
    -> Новая сессия: кнопка «Новая сессия» (Запуск сессии)
    -> Задачи: пункт сайдбара
  Новая сессия:
    kind: dialog
    -> Сессия: «Запустить» (Запуск сессии)
  Задачи:
    -> Карточка задачи: клик по задаче
  Карточка задачи:
    kind: panel
    -> Сессия: «Открыть сессию»

ignored:
  - /debug/flags — отладочная страница
```

- `start` — экран, с которого всё начинается (обычно «Запуск» с переходами по условиям: вошёл / не вошёл / первый запуск).
- Экран — `Имя экрана:` с полями под ним: `kind` (page — по умолчанию | dialog | sheet | tab | panel | external), `route`, `about`.
- Переход — строка `-> Цель: действие (Фича)` под экраном-источником. Действие и `(Фича)` необязательны: `-> Корзина`. `(Фича)` в конце — название фичи из `features/`, к которой относится переход; на экране «Приложение» по нему подсвечивается путь фичи.
- `ignored` — точки входа из кода, которые намеренно не на карте: `- точка входа — причина`.

## features/<id>.yml — фича

`<id>` — имя файла: `область.коротко` латиницей (`checkout.promo`). Его используют ссылки из отчётов «Изменения».

```yaml
feature: Промокод при оформлении
area: Оформление заказа
status: done
summary: Вводишь промокод — сумма пересчитывается со скидкой
aliases: [купон, скидка]
entries: [/checkout, app/checkout/page.tsx]
starts_at: Оформление

steps:
  - Корзина: нажать «Оформить» -> открылось Оформление  [CartSheet, app/cart/CartSheet.tsx]
  - Оформление: ввести промокод, выйти из поля -> сумма со скидкой  [applyPromo, lib/checkout.ts]
  - Оформление: нажать «Оплатить» -> экран оплаты

proofs:
  - test: lib/checkout.test.ts::applies_promo  covers: 2  at: 2026-11-25T12:00:00Z
  - video: media/3/promo.mp4  covers: 1, 2  title: Промокод в оформлении
```

| Поле | Что |
|---|---|
| `feature` | название, как сказал бы пользователь (обязательно) |
| `area` | область продукта |
| `status` | `done` работает целиком · `in_progress` сделано частично · `planned` описано, кода нет · `broken` сломано (только с доказательством) · `draft` ещё описывается |
| `summary`, `aliases` | что получает пользователь; как ещё её называют |
| `entries` | маршруты / экраны / файлы, откуда фича начинается (для сверки покрытия) |
| `starts_at` | экран из `app.yml`, где фича начинается |
| `steps` | путь пользователя по шагам |
| `paths` | вместо `steps`, если путей несколько: `Название пути:` и шаги под ним |
| `proofs` | что доказывает, что фича работает |

**Шаг:** `- Экран: действие -> результат  [Сущность, функция, путь/к/файлу.ts]`

- экран — как в `app.yml`; всё до первого `: `;
- действие и результат разделены ` -> `; результат необязателен;
- ссылки на код — в квадратных скобках в самом конце, через пробел: сущности (компоненты, функции, сторы) и файлы (с `/` или расширением, можно `файл.rs::функция`). Скобки внутри текста (`/catalog/[id]`) остаются текстом.

Шаги нумеруются по порядку с 1 (через все пути фичи); `covers` в доказательствах ссылается на эти номера.

**Доказательство:** `- вид: ссылка  covers: 1, 2  at: <ISO 8601>  title: текст`

- вид: `test` (файл или `файл::имя_теста`) · `screenshot` · `video` · `cli` (команда) · `manual` (что проверено руками);
- `covers` — номера шагов; нет — доказывает всю фичу;
- `at` — когда тест проходил / снят кадр. Если код шагов менялся позже — Stepan покажет «устарело».

## Как карта меняется

- **Stepan строит её в несколько проходов**: опись фич → детали по областям (`features/*.yml`) → навигация (`app.yml`) → доказательства → сверка покрытия с маршрутами из кода. «Синхронизировать» перепроверяет только то, что затронули коммиты с прошлой сверки.
- **Агенты обновляют её сами** в конце задачи, если поменяли пользовательское поведение (скилл `stepan-verify-flows`), и проверяют `stepan_verify flows check`.
- **Ты правишь руками** любой файл: Stepan перечитает его сразу. При записи Stepan не трогает файлы, смысл которых не изменился, — твои комментарии и порядок строк остаются.
- Старый одиночный `.stepan_verify/flows.yaml` переводится в этот формат при первом открытии (старый файл остаётся как `flows.yaml.bak`).
